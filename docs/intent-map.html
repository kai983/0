INTENT MAP - v1.4 기준

지식 저장소 의도 지도

이 대화 전체에서 요구를 뽑아 네 겹으로 나눈 것. 무엇을 만들었는지가 아니라, 무엇을 원했는지의 기록이다. 다음 작업은 이 문서에서 시작하면 된다.

기준 v1.4 정리일 2026-09-01 기기 Galaxy S23 Ultra 범위 v0.1 - v1.4 (40 커밋)

01뿌리 - 왜 만드는가

한 번만 말했지만 모든 결정의 기준이 된 문장.

"지식이 내 뇌에 다 못 들어가니, 잘 쌓아두고 내가 언제든 가장 편한 형태로 꺼내 쓸 수 있는 앱. 거기에 플러스 학습도 가능" 첫 요구 정의

여기서 세 동사가 나온다 - 쌓는다, 꺼낸다, 남긴다. 앱의 세 탭이 정확히 이 순서다. 그리고 "가장 편한 형태"라는 말이 이후 모든 디자인 요구의 뿌리였다. 기능이 되는 것과 편한 것은 다르고, 이 프로젝트에서 후자를 요구한 횟수가 훨씬 많았다.

02네 겹 - 무엇을 원했는가

표면 요구에서 밑에 깔린 기준까지, 아래로 갈수록 말수는 적고 힘은 세다.

1겹

마찰 0 - 내가 안 만져도 되게

"공유하면 아무런 클릭 없이 자동으로 내가 원하는 형태로 가공해서 저장"

  • 공유 한 번으로 저장부터 요약까지 - 앱을 먼저 열 필요 없음
  • "무료키 니가 스스로 넣어놔야지" - 설정조차 사용자 몫이 아니다
  • "ai도 여러번 해서 겨우 한번 됨" - 재시도도 사용자 몫이 아니다 (v1.4에서 앱이 대신 기다림)

이 겹의 판단 기준은 하나다. 사용자가 같은 동작을 두 번 하면 그건 앱의 결함이다.

2겹

0원 - 정액제 밖으로 돈이 나가지 않게

"돈은 정액제 외에 추가로는 안 나가고 싶고"

  • 무료 한도 안에서만 동작하고, 한도를 넘으면 과금이 아니라 대기 안내
  • 서버도 계정도 없음 - 데이터는 기기에만
  • 이 원칙 때문에 여러 기기 동기화는 보류다. 만들면 서버와 계정이 생긴다
3겹

때깔 - 기능만큼 중요한 것

"바탕화면 아이콘부터 내부 아이콘, 디자인 등 싹 다 최신 디자인 트렌드 래퍼런스 조사해서 클로드 디자인으로 다시 만들어서 교체하자"

"모든 모드를 글로벌 1티어 앱 디자인 래퍼런스를 참고해서 클로드 디자인으로 디벨롭"

  • 디자인 요구가 전체 요구의 3분의 1이 넘는다 - 부차적인 항목이 아니다
  • 핵심어는 "래퍼런스 조사해서" - 취향이 아니라 근거를 요구한다
  • "아이콘 촌스러워" - 이모지 하나까지 걸린다. 남의 그림을 빌려 쓰면 티가 난다
  • "더 디벨롭해" - 한 번 만든 것으로 끝나지 않는다. 매번 한 단계 더 올린다
4겹

검증 - 말이 아니라 확인

"기획대로 최신 버전으로 업데이트 개발 / 리뷰 철저"

"이 버전 문제 없나 모의 리뷰"

  • "됐습니다"를 믿지 않는다. 스스로 검증하고 결과를 보고해야 신뢰가 성립한다
  • 리뷰를 시켰을 때 실제로 결함이 나왔다 - v1.2에서 7건, v1.21에서 5건, v1.3에서 6건
  • 그래서 리뷰는 형식이 아니라 매 버전의 필수 공정이다

03절대 규칙

한 번 말했고, 어겼을 때 다시 지적받은 것들. 협상 대상이 아니다.

-
구분 기호는 하이픈만 "ㅡ나 • 쓰지말고 - 로 통일하라니깐" - 앱 문구, 문서, 대화 답변 전부에 적용
**
별표는 화면에 절대 안 나온다 "**는 절대 안나오게 하자" - 렌더링 실패 시 서식을 포기하더라도 기호는 지운다
#
버전은 매 변경마다 올리고 앱에 표시 작은 변경 +0.01, 큰 변경 +0.1 - 설정 화면 하단에서 지금 버전을 확인할 수 있다
키
API 키는 소스에 남기지 않는다 빌드할 때 GitHub Secret에서 주입한다. 백업 파일에도 키는 빠진다
약
로그인된 웹 AI 자동 조작은 만들지 않는다 세 번 검토했고 세 번 같은 결론 - 약관 위반이고 계정 정지 위험이 실제로 있다

05이 프로젝트가 가르친 것

같은 실수를 두 번 하지 않기 위해 남기는 항목.

  • 추측한 오류 메시지는 디버깅을 막는다. 모든 400을 "키가 잘못됨"으로 표시한 탓에 엉뚱한 곳을 오래 팠다. 메시지를 정직하게 바꾼 다음 시도에서 진짜 원인(유튜브 추적 파라미터)이 바로 나왔다
  • 기기에서만 재현되는 경로가 있다. 공유 인텐트가 만드는 URL, 네이티브 HTTP, 공유 시트 - 개발 환경에서 손으로 만든 입력은 실제 입력과 다르다. 그래서 앱이 스스로 진단을 말하게 만드는 장치(연결 테스트, 공유 상태)를 상설로 남겼다
  • 테스트는 되는 경우가 아니라 안 되는 경우를 고정해야 한다. v1.3은 "폴백이 된다"만 검증했고, 리뷰에서 폴백이 안 되는 경우 다섯 가지가 나왔다
  • 화면에 보이는 글자가 깨졌다고 폰트 문제는 아니다. 학습 카드의 가타카나는 AI가 그렇게 쓴 것이었다 - 렌더링이 아니라 프롬프트를 고쳐야 했다
지금 확인이 필요한 것 - 기기에서만 알 수 있다 1. 백업 내보내기가 공유 시트를 띄우고 파일이 실제로 저장되는지 (v0.7부터 열려 있음)
2. 새 학습 화면의 손맛 - 버튼이 눌리는 느낌과 답이 올라오는 속도
3. 자동 재시도가 실제 혼잡 상황에서 요약을 건져내는지
4. 이미 저장된 카드의 일본어 섞임은 고쳐지지 않는다 - 그 카드는 지우고 다시 만들어야 한다

06다음 사람에게

이어서 작업할 때 순서는 매번 같았고, 그 순서가 결과를 만들었다. 레퍼런스 조사 - 시안(클로드 디자인) - 확인 - 구현 - 철저 리뷰 - 실기기 확인. 중간을 건너뛴 버전은 예외 없이 되돌아왔다.

함께 보는 문서 - 기획서(제품 정의와 진단 기록), 디자인 캔버스(모든 화면 시안).
