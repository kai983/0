INTENT MAP - v1.4 기준

지식 저장소 의도 지도

대화 전체의 요구를 뿌리 하나, 기둥 넷, 가지 열여섯, 잔가지 쉰여섯으로 세운 것. 무엇을 만들었는지가 아니라 무엇을 원했고 그래서 무엇을 거절해야 하는지의 기록이다.

기준 v1.4 정리일 2026-09-01 기기 Galaxy S23 Ultra 범위 v0.1 - v1.4 (41 커밋)

00뿌리

한 번 말했고, 이후 모든 결정이 여기서 갈라져 나왔다.

"지식이 내 뇌에 다 못 들어가니, 잘 쌓아두고 내가 언제든 가장 편한 형태로 꺼내 쓸 수 있는 앱. 거기에 플러스 학습도 가능" 첫 요구 정의

동사 셋이 나온다 - 쌓는다 / 꺼낸다 / 남긴다. 앱의 세 탭이 정확히 이 순서다. 그리고 "가장 편한 형태"라는 다섯 글자가 이후 디자인 요구 전부의 출처였다. 되는 것과 편한 것은 다르고, 이 프로젝트에서 후자를 요구한 횟수가 세 배 많았다.

01네 기둥이 만드는 관문

새 요구가 들어왔을 때 통과해야 하는 순서. 위에서 걸리면 아래는 볼 필요가 없다.

02기둥 1 - 마찰 0

1

마찰 0 - 내 손이 가면 진 것

기능이 되는지가 아니라 손이 몇 번 가는지로 판단한다. 이 기둥이 요구의 절반을 차지한다.

판정 기준사용자가 같은 동작을 두 번 하게 되면, 그건 사용자의 인내심 문제가 아니라 앱의 결함이다.
1-1

수집은 공유 한 번으로 끝난다

  • 안드로이드 공유 타깃 등록 - 앱을 먼저 열 필요가 없다v0.5
  • 제목과 URL을 자동으로 갈라 저장v0.5
  • 앱이 켜져 있을 때 온 공유가 유실되던 문제 - 알림과 보관을 이중화v0.71
  • 유튜브 공유 URL의 추적 파라미터 자동 제거 (없으면 요약이 100% 실패)v0.65
1-2

재가공은 클릭 없이 일어난다

  • 공유 즉시 요약-인사이트-태그까지 자동 저장v0.6
  • 키를 사용자가 넣지 않는다 - 빌드 때 시크릿에서 주입 "무료키 니가 스스로 넣어놔야지"v0.62
  • 영상은 AI가 직접 본다 - 자막 유무와 무관v0.6
  • 학습 카드도 자동 생성v0.6
1-3

실패했을 때 기다리는 일도 앱이 한다

  • 한 모델이 막히면 다른 모델로 자동 전환 (무료 모델은 하나씩 혼잡해진다)v1.3
  • 혼잡하면 15-40-90초 뒤 스스로 재시도 "ai도 여러번 해서 겨우 한번 됨"v1.4
  • 본문 직렬화가 어긋나면 다른 방식으로 1회 자동 재시도v0.64
  • 캡처는 절대 유실하지 않는다 - AI가 실패해도 원본은 저장된 상태로 남는다원칙
1-4

다음에 뭘 할지 앱이 말해준다

  • 요약 직후 다음 단계 패널 "그 다음 뭘 해야할지 모르겠음 ux"v0.66
  • 요약이 끝나면 "다시 생성"은 조용한 버튼으로 물러난다v0.66
  • 영상 대기 시간을 초 단위로 보여주고, 무한 대기는 타임아웃으로 끊는다v0.66

03기둥 2 - 0원

2

0원 - 정액제 밖으로 한 푼도

비용 구조가 기능 선택을 지배한다. 이 기둥은 무엇을 만들지보다 무엇을 안 만들지로 증명된다.

판정 기준돈이 드는 해법은 아무리 좋아도 탈락한다. 예외는 사용자가 비용을 명시적으로 승인할 때뿐이다.
2-1

무료 한도 안에서만 동작한다

  • Gemini 무료 티어를 기기에서 직접 호출 - 중계 서버 없음v0.6
  • 한도를 넘으면 과금이 아니라 대기 안내v0.72
  • 모델 3종을 돌려 무료 용량을 최대한 긁어 쓴다v1.3
2-2

서버도 계정도 없다

  • 데이터는 기기 안에만 (localStorage) - 초기 Express+SQLite 구성을 걷어냄v0.1
  • 백업은 파일 하나 - 어디에 둘지는 사용자가 고른다v0.7
  • 백업 파일에 API 키는 넣지 않는다 - 백업은 아무 데나 가기 때문v0.7
2-3

이 기둥이 막아 세운 것

  • 여러 기기 동기화 - 서버와 계정이 생기므로 0원과 정면충돌. 보류보류
  • 유료 API 모델 - 검토 대상에 오르지 않음제외
  • 공유할 때 학습 카드까지 자동 생성 - API 사용량이 2배라 기본 꺼짐 후보로만후보

04기둥 3 - 때깔

3

때깔 - 취향이 아니라 근거

완성도는 기능의 장식이 아니라 요구 그 자체다. 다만 "예쁘게"가 아니라 "조사해서"를 요구했다.

판정 기준근거를 댈 수 없는 디자인 결정은 하지 않는다. 참조한 앱의 실제 수치를 대지 못하면 그것은 취향이다.
3-1

레퍼런스를 실측해서 옮긴다

  • 테마마다 세계 기준을 하나씩 배정 - 토스풍은 토스 TDS와 Revolutv1.2
  • 편집형은 Readwise Reader와 NYT, 인덱스형은 Linear와 Things 3v1.2
  • 몰입형은 Spotify와 Linear 다크 - 표면 사다리를 그대로 가져옴v1.2
  • 색-크기-간격을 눈대중이 아니라 실제 값으로 조사해 옮김v1.1
3-2

남의 그림을 빌려 쓰지 않는다

  • 이모지 전량 제거 - 직접 그린 일러스트로 교체 "아이콘 촌스러워"v1.3
  • 아이콘 세트를 24px 격자, 2px 선으로 통일v1.1
  • 런처 아이콘을 직접 제작 - 모노크롬 레이어까지 그려 넣음v1.1
  • 그라디언트는 AI 표시 한 곳에만 - 쓰임이 하나면 의미가 된다v1.1
3-3

한글로 읽기 좋게

  • 본명조 한글 서브셋을 앱에 내장, 읽기 본문 행간 1.8v1.2
  • 단어 단위 줄바꿈 - 긴 제목이 아무 데서나 끊기지 않게v1.2
  • 긴 문장은 가운데 정렬 금지 - 줄마다 시작점이 달라진다v1.4
  • AI 답변을 한국어로 강제 - 일본어 가나가 섞여 나온 사고 이후v1.4
3-4

손맛 - 눌리는 느낌이 있어야 한다

  • 토스식 눌림 - 회색으로 물들며 0.98로 줄고, 놓을 때 천천히 돌아온다v1.2
  • 듀오링고식 버튼 - 4px 그림자 위에 앉았다가 누르면 3px 가라앉는다v1.4
  • 테마마다 눌림이 다르다 - 밀도 높은 목록은 즉각, 다크는 밝기 한 단계v1.2
3-5

한 번 만들고 끝내지 않는다

  • 같은 학습 화면을 세 번 올림 - 카드(v0.4) 다음 정돈(v1.1) 다음 퀴즈(v1.4)v1.4
  • "더 디벨롭해"는 매번 한 단계 더 올리라는 상시 지시로 받는다상시

05기둥 4 - 신뢰

4

신뢰 - 확인된 것만 참이다

"됐습니다"는 증거가 아니다. 검증 절차와 그 결과 보고가 결과물의 일부다.

판정 기준검증을 보여주지 못한 완료는 완료가 아니다. 리뷰를 시킬 때마다 실제로 결함이 나왔다 - 7건, 5건, 6건.
4-1

앱이 거짓말하지 않는다

  • 오류를 추측하지 않는다 - 단정할 수 없으면 서버의 실제 응답을 그대로 보여준다v0.64
  • 혼잡(503)은 실패가 아니라 대기 - 빨간 글씨 대신 회색 안내v0.72
  • 지금 어떤 키를 쓰는 중인지 가려서 표시하고, 지울 수 있게v0.7
  • 연결 테스트가 실제로 답한 모델 이름을 함께 보여준다v1.31
4-2

앱이 스스로 진단한다

  • 연결 테스트 - 실기기에서 한 탭으로 상태 판정v0.64
  • 공유 상태 진단 - 공유해도 아무 일이 없을 때 무엇을 받았는지 보여준다v0.71
  • 기기에서만 재현되는 경로가 있으므로, 진단 장치는 임시가 아니라 상설이다원칙
4-3

리뷰는 취향이 아니라 공정이다

  • v1.2 구현 리뷰 7건 - 상세 태그 누락, 긴 제목 가로 넘침 등 전부 실재v1.2
  • 전체 리뷰 5건 - 달력 주 오분류, 연도 누락v1.21
  • 모의 리뷰 6건 - 폴백이 필요한 상황에서 폴백이 안 되던 경우들v1.31
  • 테스트는 되는 경우가 아니라 안 되는 경우를 고정한다 - v1.3의 교훈v1.31
  • 회귀 12종 상시 - 매 배포 전 전량 통과가 조건상시
4-4

기기에서만 참이 되는 것이 있다

  • 유튜브 공유 URL의 추적 파라미터 - 손으로 쓴 URL로는 영원히 못 잡는다v0.65
  • 앱이 켜져 있을 때의 공유 유실 - 브라우저에서는 재현되지 않았다v0.71
  • 백업 내보내기의 안드로이드 경로 - 아직 확인 안 됨미확인

07요구를 읽는 법

말은 짧고 요구는 여러 개다. 한 줄을 한 건으로 받으면 반은 놓친다.

"학습 쪽 글자 깨진다 / 퀴즈로 하든가 카드로 하든가 답보기 이 양식 이상해 / 듀오링고를 참고하든가 / 더 디벨롭해 / 그리고 ai도 여러번 해서 겨우 한번 됨" v1.4를 부른 한 메시지 - 여기에 독립된 요구가 다섯 개 들어 있다

  • 깨진 글자 - 원인 규명 요구 (결과: 폰트가 아니라 AI 출력 문제였다)
  • 양식이 이상하다 - 형식 자체를 다시 정하라는 요구, 부분 수정이 아님
  • 퀴즈로 하든가 카드로 하든가 - 어정쩡한 중간을 버리고 하나를 고르라는 요구
  • 듀오링고를 참고하든가 - 근거로 쓸 레퍼런스 지정 (기둥 3의 발동)
  • ai도 여러번 - 별개의 안정성 결함 보고 (기둥 1의 발동)

읽는 규칙 셋. 첫째, 슬래시와 줄바꿈은 요구의 경계다. 둘째, "이상해"는 부분 수정이 아니라 재설계 요구다. 셋째, 레퍼런스 이름이 나오면 그것은 힌트가 아니라 기준이다.

09이 프로젝트가 가르친 것

  • 추측한 오류 메시지는 디버깅을 막는다. 모든 400을 "키가 잘못됨"으로 표시한 탓에 엉뚱한 곳을 오래 팠다. 메시지를 정직하게 바꾼 다음 시도에서 진짜 원인이 바로 나왔다
  • 고장난 기능 뒤에는 한 번도 검증되지 않은 기능이 줄지어 숨는다. 요약이 처음 끝까지 돌자마자 별표 문제와 다음 행동 부재가 한꺼번에 드러났다
  • 테스트는 되는 경우가 아니라 안 되는 경우를 고정해야 한다. v1.3은 "폴백이 된다"만 검증했고, 폴백이 안 되는 경우 다섯 가지가 리뷰에서 나왔다
  • 화면의 글자가 깨졌다고 폰트 문제는 아니다. 학습 카드의 가타카나는 AI가 그렇게 쓴 것이었다 - 고칠 곳은 렌더러가 아니라 프롬프트였다
  • 안 보이는 코드는 죽은 코드다. 사이드바는 v0.2 이후 어떤 너비에서도 화면에 나오지 않았는데 v1.3까지 살아 있었다

10일하는 순서

매번 같은 순서였고, 그 순서가 결과를 만들었다. 중간을 건너뛴 버전은 예외 없이 되돌아왔다.

  • 1. 레퍼런스 조사 - 무엇을 참조할지 정하고 실제 수치를 뽑는다
  • 2. 시안 - 클로드 디자인 캔버스에 아트보드로 그린다
  • 3. 확인 - 시안을 보여주고 방향을 확정받는다
  • 4. 구현 - 토큰부터 화면까지, 시안을 코드로 옮긴다
  • 5. 리뷰 - 코드 리뷰를 돌리고 나온 것을 전부 고친다
  • 6. 검증 - 회귀 전량 + 4개 테마 스크린샷 + APK 내용물 대조
