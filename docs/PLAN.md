## 1. 제품 정의

공유 한 번으로 지식이 AI 요약과 함께 쌓이고, 학습 카드로 되살아나는 개인 지식 앱.
유튜브 - 기사 - 리포트 - 글을 공유하면 앱이 알아서 저장하고, Gemini 무료 API가
요약 - 인사이트 - 태그를 붙이며, 간격 반복 학습으로 기억까지 책임진다. 추가 비용은 0원.

앱 이름이 지식 아카이브에서 지식 저장소로 바뀌었다. 패키지 ID는 그대로라 업데이트로 얹힌다.

- 재가공은 AI가, 비용은 0원 - "돈은 정액제 외에 추가로는 안 나가고 싶고"

## 4. 진단 기록 - AI 자동 요약은 왜 안 됐나

증상: 실기기에서 "API 키가 올바르지 않아요"가 반복. 키를 새로 만들어 저장해도 동일.

검증 순서와 결과:

1. 키가 만료됐거나 형식이 잘못됐나 - 아니다. 키 2개 모두 실제 호출에서 정상 응답
2. 테스트 환경이 성공을 흉내내나 - 아니다. 가짜 키는 정확히 거부됨 (대조 실험)
3. 모델이 안 열렸나 - 열려 있다. 모델 목록 조회 결과 38개 사용 가능
4. 폰이 보내는 요청 자체가 다른가 - 그렇다. 다만 여기서 앱이 모든 400을 "키가 잘못됨"으로
   표시한다는 사실이 먼저 드러났다. v0.64에서 실제 원인 문구를 그대로 노출하도록 수정
5. **정직해진 메시지가 원인을 지목 - "Request contains an invalid argument".** 유튜브 앱은
   공유할 때 항상 `?si=` 추적 파라미터를 붙이는데, 영상 URI에 그게 붙으면 서버가 요청 전체를
   거부한다. 재현 실험에서 파라미터가 붙은 URL만 400, 깨끗한 URL은 정상 요약. 그래서 실기기
   공유는 100% 실패하고 개발 환경의 손으로 쓴 URL은 성공했다

v0.64 조치:

- 키를 헤더와 URL 쿼리 양쪽으로 함께 전송 (한쪽 누락돼도 인증)
- 본문 형식 오류 시 다른 직렬화 방식으로 1회 자동 재시도
- 400을 키 탓으로 단정하지 않고 서버의 실제 원인 문구 노출
- 설정에 연결 테스트 버튼 추가 (실기기에서 한 탭으로 판정)
- 모델을 버전 고정에서 최신 별칭으로 변경

v0.65 조치:

- 유튜브 링크는 영상 ID만 뽑아 표준 주소로 재구성해 전송. 짧은 링크, 쇼츠, 모바일 도메인,
  파라미터 다중 형식까지 6가지를 테스트로 고정
- 기사 URL은 기존 경로 유지

끝맺음: v0.65를 올린 실기기에서 유튜브 공유 요약이 정상 동작함을 확인했다. 그리고 파이프라인이
처음으로 끝까지 돌자 가려져 있던 하류 문제 두 개가 드러났다 - 요약의 굵은 글씨가 별표로 보였고
(렌더러에 인라인 서식이 없었다), 요약이 끝난 화면의 가장 큰 버튼이 "다시 생성"이라 다음 행동을
알 수 없었다. 둘 다 v0.66에서 수정. 고장난 기능 뒤에는 한 번도 검증되지 않은 기능이 줄지어 숨는다.

교훈 두 가지. 첫째, 추측한 오류 메시지는 디버깅을 막는다 - "키가 잘못됨"이라는 단정 하나
때문에 엉뚱한 곳을 오래 팠고, 메시지를 정직하게 바꾼 다음 시도에서 원인이 바로 나왔다.
둘째, 기기에서만 재현되는 경로(공유 인텐트가 만드는 URL, 네이티브 HTTP)가 있으므로 개발
환경에서 손으로 만든 입력은 실제 입력과 다르다. 앱 스스로 진단 결과를 말하게 만드는 장치가
기능만큼 중요하다. 연결 테스트는 상설 기능으로 남긴다.

## 5. 판단 - 수정인가 신규인가

수정 유지. 실패 원인은 아키텍처가 아니라 오류 처리 한 군데였다. 로컬 퍼스트 + Capacitor +
무료 API 직접 호출 구성은 0원 - 오프라인 - Android 제약을 그대로 만족한다.
신규가 정당해지는 조건은 여러 기기 실시간 동기화가 필요해질 때 하나뿐이다.

## 7. 지키는 원칙

- 추가 비용 0원 - 무료 한도 안에서만, 한도 초과 시 과금 대신 대기 안내
- API 키는 기기에만 저장, 소스 코드에도 남기지 않는다
- 로그인된 웹 AI 자동 조작은 약관 위반 - 계정 정지 위험이라 만들지 않는다
- 캡처는 절대 유실하지 않는다 - AI 실패해도 원본은 남는다
- 오류 메시지는 추측하지 않는다 - 단정할 수 없으면 실제 응답을 그대로 보여준다 (v0.64 추가)
- 디자인 결정은 취향이 아니라 실측을 근거로 한다 - 참조한 앱의 실제 수치(색-크기-간격)를 조사해 옮긴다 (v1.1 추가)
- 하이픈 통일, 버전 표기는 계속 유지한다

## 8. 마감 - 무엇이 완성됐고, 무엇이 남았나

v1.0은 "요구한 것이 전부 동작한다"는 뜻이다. 완벽하다는 뜻은 아니다.

**완성된 것** - 유튜브나 기사를 공유하면 클릭 없이 저장되고, AI가 영상을 직접 보거나 원문을
읽어 한 줄 요약-핵심-인사이트-태그로 정리한다. 검색과 태그로 꺼내 보고, 학습 카드로 간격을
두고 다시 만난다. 전부 추가 비용 0원이고, 파일 하나로 백업된다.

**솔직하게 남은 것** - 백업 내보내기의 안드로이드 경로는 아직 실기기에서 확인되지 않았다.
브라우저에서는 내보내기-가져오기-중복 방지-잘못된 파일 거부까지 전부 통과했지만, 이
프로젝트에서 두 번(유튜브 URL, 공유 유실) 배운 것이 기기에서만 재현되는 경로는 기기에서만
확인된다는 사실이다.

1. 백업 내보내기 - 공유 시트가 뜨고 드라이브나 메신저에 파일이 실제로 저장되는지
2. 백업 가져오기 - 그 파일로 지식이 돌아오는지

이 둘이 확인되면 v1.0은 문자 그대로 끝이다. 문제가 있으면 v1.01로 고친다.

**앞으로의 후보** (필요해지면 그때)

- 오늘의 지식 - 오래된 항목 재노출
- 공유 시 학습 카드 자동 생성 (기본 꺼짐 - API 사용량 2배)
- 정렬 옵션, 폴더나 묶음
- 여러 기기 동기화 - 구조를 바꿔야 하고 서버와 계정이 생기므로 0원 원칙과 충돌한다.
  정말 필요해질 때 다시 판단한다.

## 9. 디자인 사이클 - v1.1에서 v1.21까지

기능이 닫힌 뒤의 요청: "모든 모드를 글로벌 1티어 앱 디자인 래퍼런스를 참고해서 클로드
디자인으로 디벨롭". 매 단계가 같은 순서로 돌았다 - 레퍼런스 실측 조사, 클로드 디자인 캔버스
시안, 확인 후 구현, 그리고 철저 리뷰.

테마마다 세계 기준을 하나씩 정했다. 네 테마가 서로 다른 회수 방식(훑기 - 읽기 - 찾기 - 밤)을
맡고 있으므로 참조 대상도 각자 다르다.

- 토스풍 (훑기) - 토스 TDS와 Revolut. 카드 대신 여백으로 구분하는 전면 행, 누르면 회색으로
  물들며 0.98로 줄어드는 눌림, 8px 각진 칩, 화면당 파란 요소 하나의 절제
- 편집형 (읽기) - Readwise Reader와 NYT. 본명조(한글 2,350자 서브셋 약 600KB) 내장으로
  제목-본문은 세리프, UI는 프리텐다드. 헤어라인 구분, 첫 문장 위 테라코타 리드 규칙, 본문 행간 1.8
- 인덱스형 (찾기) - Linear와 Things 3. 48px 장부 행에 출처 색점, 한 줄 제목, 오른쪽 고정
  날짜 열의 세로 정렬. 날짜 그룹 헤더에 개수
- 몰입형 (밤) - Spotify와 Linear 다크. 표면 사다리(#0B0C0E - #141519 - #22242A)로 테두리
  없이 밝기만으로 깊이 표현, 앰버 액센트, 상세 상단의 앰비언트 글로우

리뷰가 실제로 잡은 것 - v1.2 구현 리뷰 7건과 전체 리뷰 5건, 총 12건 모두 수정. 사용자 눈에
보였을 것들: 인덱스 테마에서 상세 페이지 태그가 첫 개만 보이던 버그, 띄어쓰기 없는 긴 한글
제목의 가로 넘침, "이번 주" 그룹이 달력상 지난주 항목을 포함하던 문제, 작년 항목 날짜의 연도
누락. 회귀 테스트 10종과 달력 주 단위 테스트 8케이스가 이 상태를 지킨다.

실기기에서 확인할 것 - 토스풍 눌림의 손맛(속도-스케일), 편집형 세리프의 실제 렌더링, 그리고
8절부터 남아 있는 백업 내보내기의 안드로이드 경로.
