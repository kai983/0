기준 버전 v0.65 - 갱신일 2026-09-01 - 플랫폼 Android (Galaxy S23 Ultra)

정식 문서(디자인 반영본): https://claude.ai/code/artifact/9929f461-51db-49a7-b6c6-ec5e16affef6

## 1. 제품 정의

공유 한 번으로 지식이 AI 요약과 함께 쌓이고, 학습 카드로 되살아나는 개인 지식 앱.
유튜브 - 기사 - 리포트 - 글을 공유하면 앱이 알아서 저장하고, Gemini 무료 API가
요약 - 인사이트 - 태그를 붙이며, 간격 반복 학습으로 기억까지 책임진다. 추가 비용은 0원.

앱 이름이 지식 아카이브에서 지식 저장소로 바뀌었다. 패키지 ID는 그대로라 업데이트로 얹힌다.

## 4. 진단 기록 - AI 자동 요약은 왜 안 됐나

증상: 실기기에서 "API 키가 올바르지 않아요"가 반복. 키를 새로 만들어 저장해도 동일.

검증 순서와 결과:

1. 키가 만료됐거나 형식이 잘못됐나 - 아니다. 키 2개 모두 실제 호출에서 정상 응답
2. 테스트 환경이 성공을 흉내내나 - 아니다. 가짜 키는 정확히 거부됨 (대조 실험)
3. 모델이 안 열렸나 - 열려 있다. 모델 목록 조회 결과 38개 사용 가능
4. 폰이 보내는 요청 자체가 다른가 - 그렇다. 다만 여기서 앱이 모든 400을 "키가 잘못됨"으로
   표시한다는 사실이 먼저 드러났다. v0.64에서 실제 원인 문구를 그대로 노출하도록 수정
5. **정직해진 메시지가 원인을 지목 - "Request contains an invalid argument".** 유튜브 앱은
   공유할 때 항상 `?si=` 추적 파라미터를 붙이는데, 영상 URI에 그게 붙으면 서버가 요청 전체를
   거부한다. 재현 실험에서 파라미터가 붙은 URL만 400, 깨끗한 URL은 정상 요약. 그래서 실기기
   공유는 100% 실패하고 개발 환경의 손으로 쓴 URL은 성공했다

v0.64 조치:

- 키를 헤더와 URL 쿼리 양쪽으로 함께 전송 (한쪽 누락돼도 인증)
- 본문 형식 오류 시 다른 직렬화 방식으로 1회 자동 재시도
- 400을 키 탓으로 단정하지 않고 서버의 실제 원인 문구 노출
- 설정에 연결 테스트 버튼 추가 (실기기에서 한 탭으로 판정)
- 모델을 버전 고정에서 최신 별칭으로 변경

v0.65 조치:

- 유튜브 링크는 영상 ID만 뽑아 표준 주소로 재구성해 전송. 짧은 링크, 쇼츠, 모바일 도메인,
  파라미터 다중 형식까지 6가지를 테스트로 고정
- 기사 URL은 기존 경로 유지

교훈 두 가지. 첫째, 추측한 오류 메시지는 디버깅을 막는다 - "키가 잘못됨"이라는 단정 하나
때문에 엉뚱한 곳을 오래 팠고, 메시지를 정직하게 바꾼 다음 시도에서 원인이 바로 나왔다.
둘째, 기기에서만 재현되는 경로(공유 인텐트가 만드는 URL, 네이티브 HTTP)가 있으므로 개발
환경에서 손으로 만든 입력은 실제 입력과 다르다. 앱 스스로 진단 결과를 말하게 만드는 장치가
기능만큼 중요하다. 연결 테스트는 상설 기능으로 남긴다.

## 5. 판단 - 수정인가 신규인가

수정 유지. 실패 원인은 아키텍처가 아니라 오류 처리 한 군데였다. 로컬 퍼스트 + Capacitor +
무료 API 직접 호출 구성은 0원 - 오프라인 - Android 제약을 그대로 만족한다.
신규가 정당해지는 조건은 여러 기기 실시간 동기화가 필요해질 때 하나뿐이다.

## 7. 지키는 원칙

- 추가 비용 0원 - 무료 한도 안에서만, 한도 초과 시 과금 대신 대기 안내
- API 키는 기기에만 저장, 소스 코드에도 남기지 않는다
- 로그인된 웹 AI 자동 조작은 약관 위반 - 계정 정지 위험이라 만들지 않는다
- 캡처는 절대 유실하지 않는다 - AI 실패해도 원본은 남는다
- 오류 메시지는 추측하지 않는다 - 단정할 수 없으면 실제 응답을 그대로 보여준다 (v0.64 추가)
- 하이픈 통일, 버전 표기는 계속 유지한다
